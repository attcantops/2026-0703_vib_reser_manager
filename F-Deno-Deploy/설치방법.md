# 진동시험기 예약 웹앱 — Deno Deploy 버전 설치/실행 안내

## (a) Deno Deploy가 뭔가요? (한 문단)
**Deno Deploy**는 전 세계 엣지(edge) 위치에서 코드를 실행하는 TypeScript/JavaScript **네이티브** 서버리스 런타임입니다. 별도 빌드나 컴파일 없이 `.ts` 파일을 그대로 올리면 `Deno.serve()`가 요청을 받아 처리하고, 데이터는 런타임에 **내장된 키-값 저장소 Deno KV(`Deno.openKv()`)**에 저장합니다. 성격은 Cloudflare Workers와 매우 비슷하지만(엣지·경량·글로벌), Cloudflare가 자체 런타임/생태계를 쓰는 것과 달리 Deno Deploy는 **Deno 생태계**(표준 라이브러리, `deno` CLI, `deployctl`)를 그대로 사용한다는 점이 다릅니다.

## (b) 가입
1. https://deno.com/deploy 접속 → **GitHub 계정으로 로그인**(가입).
2. 조직/프로젝트를 하나 만들면 배포 준비 끝. (신용카드 없이 무료 티어로 시작 가능)

## (c) 로컬에서 실행하기
1. **Deno 설치** (한 번만):
   - macOS/Linux: `curl -fsSL https://deno.land/install.sh | sh`
   - Windows(PowerShell): `irm https://deno.land/install.ps1 | iex`
   - 설치 확인: `deno --version`
2. 이 폴더에서 개발 서버 실행:
   ```
   deno task dev
   ```
   → 브라우저에서 **http://localhost:8000** 접속.
   - `deno task dev`는 내부적으로 `deno run --unstable-kv --allow-net --allow-read --watch main.ts`를 실행합니다.
   - **`--unstable-kv`**: Deno 버전에 따라 Deno KV가 아직 unstable일 수 있어 붙였습니다. 최신 Deno에서 KV가 안정화되어 있다면 이 플래그 없이도 동작하며, 그때는 `deno.json`의 tasks에서 빼도 됩니다.
   - 로컬에서는 KV 데이터가 로컬 SQLite 파일에 저장되고, Deno Deploy에 올리면 자동으로 글로벌 분산 KV가 사용됩니다(코드 변경 불필요).

## (d) 배포하기
**방법 1 — deployctl (CLI):**
```
deno install -Arf jsr:@deno/deployctl      # deployctl 설치(한 번만)
deployctl deploy --project=<프로젝트이름> --entrypoint=main.ts
```
**방법 2 — GitHub 연동 자동배포(권장):**
1. 이 폴더를 GitHub 저장소로 push.
2. Deno Deploy 대시보드 → **New Project → GitHub 저장소 선택 → entrypoint를 `main.ts`로 지정**.
3. 이후 `main` 브랜치에 push할 때마다 자동으로 재배포됩니다. Deno KV는 배포 프로젝트에 자동 연결되므로 별도 DB 설정이 필요 없습니다.

## (e) 다른 플랫폼(특히 Cloudflare B안)과 비교
- **같은 점**: 둘 다 엣지 런타임이고, 정적 HTML + `fetch("/api/*")` 구조가 동일해 `public/index.html`은 사실상 그대로 이식됩니다.
- **다른 점**: Deno는 TS를 빌드 없이 바로 실행하고 저장소로 **Deno KV**를 쓰는 반면, Cloudflare는 Wrangler로 배포하고 KV/D1 등 자체 스토리지를 씁니다. (구글시트 A안은 스프레드시트가 곧 DB인 점이 가장 큰 차이)

## (f) Deno KV 특성 (한 줄)
Deno KV는 **글로벌로 분산되는 키-값 저장소**로, `atomic()`의 check-and-set으로 `(machine,date,hour)` 키의 중복예약을 원천 차단하며 강한 일관성으로 커밋됩니다.
