# 외부 접속 설정 계획 — Cloudflare Tunnel + Access

이 앱을 **사외(인터넷)에서 접속**할 수 있게 만드는 방법과 그 판단 근거를 정리한 문서입니다.
사내망에서만 쓸 경우 이 문서는 필요 없습니다.

---

## 1. 왜 그냥 열면 안 되는가

이 앱은 **로그인이 없고, 예약 삭제가 공개**입니다.
`pb_migrations/1700000000_init_reservations.js` 에 그렇게 정의돼 있습니다.

| 동작 | 규칙 | 의미 |
|---|---|---|
| 조회 · 등록 · **삭제** | `""` | **인증 없이 누구나** |
| 수정 | `null` | 관리자만 |

사내 폐쇄망에서 로그인 없이 편하게 쓰라고 **의도적으로** 그렇게 만든 설계입니다.
그 환경에서는 합리적입니다. 문제는 인터넷에 노출할 때입니다.

> **주소를 아는 사람은 누구나 예약 전체를 삭제할 수 있습니다.**
> 앱 화면은 이름이 맞아야 취소되지만, 그건 화면상의 제약일 뿐
> API를 직접 호출하면 적용되지 않습니다.

따라서 외부 접속은 "통로를 뚫는" 문제가 아니라 **"인증을 어디에 붙이느냐"** 의 문제입니다.

---

## 2. 요구 조건

| 조건 | 이유 |
|---|---|
| **URL로만 접속** | 접속자 기기에 앱·클라이언트 설치 불가 |
| **고정 주소** | 서버 상시 가동. 재시작마다 주소가 바뀌면 못 씀 |
| **인증 필요** | 1장의 삭제 위험 |
| **앱 코드 수정 없이** | 사내망 사용자의 편의(로그인 없음)를 유지해야 함 |

---

## 3. 방법 비교

| 방법 | 고정 URL | 도메인 | 인증 | 판정 |
|---|---|---|---|---|
| **Cloudflare Tunnel + Access** | ✅ | 필요 | **이메일 OTP** | **채택** |
| Cloudflare Quick Tunnel | ❌ 재시작마다 변경 | 불필요 | 없음 | 단기 테스트용 |
| Tailscale (VPN) | ✅ | 불필요 | 기기 인증 | 접속자마다 앱 설치 필요 → 탈락 |
| Tailscale Funnel | ✅ | 불필요 | 없음 | 인증 부재 |
| Funnel/터널 + Caddy 기본인증 | ✅ | 불필요 | 공용 비밀번호 | 무료 대안. 사용자별 구분 불가 |
| 포트포워딩 + DDNS | ✅ | 필요 | 없음 | 공인 IP 노출. 비권장 |

### Cloudflare Access를 고른 이유

**앱을 고치지 않고 인증이 생깁니다.** 터널 앞단에서 Cloudflare가 먼저 막기 때문에,
인증을 통과하지 못한 요청은 **예약 API에 닿지도 못합니다.**
1장의 위험이 앱 수정 없이 해소됩니다.

- 무료 플랜 50 사용자 — 이 용도에 충분
- 공유기 포트 개방 불필요, HTTPS 자동
- 서버의 공인 IP가 노출되지 않음

### 도메인은 개인 도메인으로

회사 도메인(`cantops.biz`)을 쓰려면 네임서버를 Cloudflare로 옮겨야 하고,
그건 회사 도메인 관리자의 승인 사안입니다.

**그런데 사내망에서는 이 기능 자체를 쓰지 않습니다.** 결국 안 쓸 기능 때문에
승인 절차를 밟는 것은 낭비입니다. 개인 도메인이면 `.com` 기준 **연 $10~11** 이고
결재 없이 당일 처리됩니다.

> Cloudflare에서 직접 구매하면 DNS가 이미 Cloudflare에 있어
> 네임서버 이전·전파 대기(최대 24시간)가 없습니다.

## 4. 설치 절차

### 4-0. 사전 준비

- Cloudflare 계정
- Cloudflare에 등록된 도메인 (대시보드 → **Domain Registration → Register Domains**)
- 서버(라즈베리파이/NAS)에서 앱이 `127.0.0.1:8090` 으로 동작 중

### 4-1. cloudflared 설치

```bash
ARCH=$(dpkg --print-architecture)
curl -fsSL -o /tmp/cf.deb \
  "https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-linux-${ARCH}.deb"
sudo dpkg -i /tmp/cf.deb && rm -f /tmp/cf.deb
cloudflared --version
```

### 4-2. Cloudflare 계정 연결

```bash
cloudflared tunnel login
```

브라우저 링크가 출력됩니다. **직접 열어 도메인을 선택**하면 인증서가 저장됩니다.

### 4-3. 터널 생성 및 DNS 연결

```bash
cloudflared tunnel create vibres
cloudflared tunnel route dns vibres vib.<내도메인>
```

### 4-4. 설정 파일

`/etc/cloudflared/config.yml`

```yaml
tunnel: vibres
credentials-file: /root/.cloudflared/<터널ID>.json

ingress:
  - hostname: vib.<내도메인>
    service: http://127.0.0.1:8090
  - service: http_status:404
```

### 4-5. 서비스 등록 (재부팅해도 유지)

```bash
sudo cloudflared service install
sudo systemctl enable --now cloudflared
systemctl is-active cloudflared
```

### 4-6. Access 정책 — **이 단계를 빼면 안 됩니다**

Cloudflare 대시보드 → **Zero Trust → Access → Applications → Add an application**

| 항목 | 값 |
|---|---|
| 유형 | Self-hosted |
| Application domain | `vib.<내도메인>` |
| Policy action | Allow |
| Include | **Emails** → 허용할 이메일 주소 |
| 인증 방법 | One-time PIN (이메일로 6자리 코드) |

> ⚠️ **4-6을 건너뛰면 4-5까지만으로도 사이트는 열립니다.**
> 그 상태는 인증 없는 공개이며, 1장의 삭제 위험이 그대로입니다.
> 반드시 Access 정책까지 적용한 뒤 주소를 사용하세요.

## 5. 완료 후 동작

```
폰 브라우저 → https://vib.<내도메인>
            → 이메일 입력 화면 (Cloudflare Access)
            → 메일로 온 6자리 코드 입력
            → 예약 화면
```

- 접속자 기기에 **앱 설치 불필요**
- 주소 **고정**, 서버 재부팅해도 유지
- 세션이 유지되므로 매번 인증하지는 않음

## 6. 관리자 화면 정책

서버에 **관리자 접근 IP 제한**을 걸어두면, 외부에서는 관리자 화면에 로그인할 수 없습니다.

```bash
# 사내/사설 대역만 허용. 127.0.0.1 을 넣으면 터널 경유 요청이 통과하므로 제외한다.
sudo <설치경로>/pocketbase superuser ips 192.168.0.0/24
```

> **왜 `127.0.0.1` 을 넣으면 안 되는가**
> 터널로 들어온 요청은 `cloudflared` 가 `localhost:8090` 으로 전달하기 때문에,
> 서버 입장에서 출발지가 `127.0.0.1` 로 보입니다. 화이트리스트에 넣으면
> 오히려 외부 접속이 관리자 인증을 통과하게 됩니다.

이렇게 두면 **예약 화면은 밖에서, 관리는 안에서** 라는 구분이 생깁니다.
외부에서도 관리가 필요하면 해당 대역을 추가하거나 제한을 해제하면 됩니다.

## 7. 운영 명령

```bash
sudo systemctl status cloudflared        # 상태
sudo systemctl stop cloudflared          # 외부 접속 차단 (즉시)
sudo systemctl start cloudflared         # 재개
sudo journalctl -u cloudflared -f        # 로그
cloudflared tunnel list                  # 터널 목록
```

**외부 접속을 잠시 끊고 싶으면 `stop` 하나면 됩니다.** 사내망 접속은 영향받지 않습니다.

## 8. 사내 환경으로 옮길 때

**사내망에서는 이 문을 쓰지 않습니다.** 직원들은 서버에 직접 접속하고,
지금처럼 로그인 없이 이름만 적고 예약하는 방식 그대로입니다.

사외 접속이 정식 요구사항이 되면 두 가지 선택지가 있습니다.

1. **주소만 교체** — `vib.cantops.biz` 로 바꾸고 같은 구조 유지 (회사 도메인 협의 필요)
2. **앱에 인증 도입** — PocketBase 내장 인증을 켜고 규칙을 바꿈
   ```
   createRule = "@request.auth.id != ''"
   deleteRule = "@request.auth.id != ''"
   ```
   예약 레코드에 소유자 필드를 두면 **"본인만 취소"** 를 DB 레벨에서 강제할 수 있습니다.
   지금은 화면에서 이름을 비교하는 방식이라 API로 우회됩니다.

⚠️ 2번은 **설계 변경**입니다. "로그인 없이 편하게"라는 현재 전제를 버리는 것이라,
사내 사용자의 편의와 맞바꾸는 결정입니다. 사내망 전용으로 간다면 하지 않는 것이 맞습니다.
