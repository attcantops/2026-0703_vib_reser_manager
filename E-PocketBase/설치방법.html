진동시험기 예약 — PocketBase 버전 설치방법

0. PocketBase가 뭔가요? (1문단)

PocketBase는 Go로 만든 단일 실행파일 백엔드입니다. 파일 하나만 실행하면 그 안에
SQLite 데이터베이스 + 자동 REST API + 웹 관리자 UI + 로그인/파일저장이 전부 들어 있습니다.
서버 프로그램을 따로 설치하거나 DB를 세팅할 필요가 없고, pocketbase serve 명령 하나로 백엔드가 뜹니다.
정적 웹페이지(HTML/JS)는 pb_public/ 폴더에 두면 같은 서버가 함께 서빙해 줍니다.

가입은 없습니다. 실행파일만 받으면 끝이고, 계정·서버·요금제가 없습니다.
만드는 "관리자 계정"도 그 서버 안 SQLite 파일에만 저장되는 로컬 계정이라, 외부로 나가는 정보가 없습니다.
사내망 폐쇄 환경에 적합합니다. (Supabase·Vercel·Cloudflare 방식은 모두 외부 계정이 필요합니다)

1. 이 폴더의 구성

E-PocketBase/
  pb_public/                     예약 화면 (정적 웹)
    index.html
    lib/pocketbase.umd.js        JS SDK — 인터넷 없이 동작하도록 내장(CDN 미사용)
  pb_migrations/
    1700000000_init_reservations.js   reservations 컬렉션 자동 생성
  install.sh                     [담당자] 최초 1회 설치 (라즈베리파이/리눅스/NAS)
  update.sh                      [운영자] 이후 업데이트 — SSH 접속해서 실행
  Dockerfile / docker-compose.yml   시놀로지·QNAP 등 Docker 전용 NAS용
  pb_schema.json                 참고용 스키마 덤프 (설치에는 불필요)

컬렉션을 손으로 만들 필요가 없습니다. pb_migrations/ 안의 파일이 첫 실행 때
reservations 컬렉션 + 중복방지 인덱스 + API 권한까지 자동으로 만듭니다.
pb_schema.json은 실제로 생성된 결과를 덤프해 둔 참고 자료이며, 임포트할 필요가 없습니다.

2. 운영 시나리오

단계 누가 무엇을
최초 1회 담당자 install.sh 실행 (아래 3장)
이후 계속 운영자 SSH 접속 → update.sh 실행 (아래 5장)

예약 데이터는 /opt/vibres/pb_data 에 저장되며 저장소 바깥입니다.
소스를 몇 번을 업데이트해도 예약 데이터는 지워지지 않습니다.

3. 최초 설치 — 담당자에게 요청할 내용

라즈베리파이 / 리눅스 서버 / SSH 되는 NAS에서 아래 한 줄만 실행하면 됩니다.

curl -fsSL https://raw.githubusercontent.com/attcantops/2026-0703_vib_reser_manager/main/E-PocketBase/install.sh | sudo bash

스크립트가 자동으로 처리하는 것:

  1. CPU 아키텍처 판별 (arm64 / armv7 / amd64) 후 PocketBase 최신판 설치
  2. 저장소를 /opt/vibres/repo 로 clone
  3. systemd 서비스 등록 — 재부팅해도 자동 실행
  4. 기동 확인 후 접속 주소 출력

끝나면 이런 주소가 표시됩니다.

  • 예약 화면: http://<서버IP>:8090/
  • 관리자 화면: http://<서버IP>:8090/_/

설치 직후 1회만 할 일 — 관리자 계정 만들기

브라우저로 http://<서버IP>:8090/_/ 에 접속하면 이메일/비밀번호를 만들라고 나옵니다.
터미널에서 바로 만들려면:

sudo /opt/vibres/pocketbase --dir=/opt/vibres/pb_data superuser upsert <이메일> <비밀번호>

(upsert 는 없으면 생성, 있으면 비밀번호 변경 — 비밀번호를 잊었을 때도 이 명령으로 재설정합니다)

포트를 바꾸고 싶다면

curl -fsSL <위 URL> | sudo PORT=8095 bash

4. 시놀로지 / QNAP (Docker 전용 NAS)

SSH가 안 되거나 Docker로만 올려야 하는 NAS는 이쪽을 씁니다.

git clone https://github.com/attcantops/2026-0703_vib_reser_manager.git
cd 2026-0703_vib_reser_manager/E-PocketBase
docker compose up -d --build
  • 시놀로지: Container Manager → 프로젝트 → 생성 에서 이 폴더를 지정해도 됩니다.
  • 8090 포트가 이미 쓰이고 있으면 docker-compose.yml 의 "8090:8090" 에서 왼쪽 숫자만 바꾸세요.
  • 예약 데이터는 호스트의 ./pb_data 폴더에 남습니다. 이 폴더만 백업하면 전체 백업입니다.

업데이트:

git pull && docker compose up -d --build

5. 업데이트 / 디버깅 (설치 이후)

담당자를 다시 부를 필요 없이, SSH로 접속해서 실행합니다.

ssh <계정>@<서버IP>
sudo /opt/vibres/repo/E-PocketBase/update.sh

하는 일: 최신 소스 git pull → 서비스 재시작 → 정상 기동 확인.
기동에 실패하면 로그를 자동으로 보여주고, 되돌릴 방법을 안내합니다.

명령 용도
sudo .../update.sh 소스만 최신으로 (평상시 이것만)
sudo .../update.sh --pb PocketBase 실행파일도 최신 버전으로 (DB 자동 백업 후 진행)
sudo .../update.sh --rollback 직전 커밋으로 되돌리고 재시작
sudo systemctl status vibres 현재 상태
sudo journalctl -u vibres -f 실시간 로그

화면(HTML/CSS/JS)만 고치는 작업은 이 저장소에서 커밋·푸시한 뒤 update.sh 한 번이면 반영됩니다.

6. 데이터 백업 / 복구

# 백업 — 이 폴더 하나가 전부입니다
sudo tar czf ~/vibres-backup-$(date +%Y%m%d).tar.gz -C /opt/vibres pb_data

# 복구
sudo systemctl stop vibres
sudo tar xzf ~/vibres-backup-YYYYMMDD.tar.gz -C /opt/vibres
sudo systemctl start vibres

관리자 화면 Settings → Backups 에서 GUI로 백업/다운로드할 수도 있습니다.

7. 데이터 구조 (reservations)

필드 타입 필수 비고
machine text O 예: 진동시험기 1호
date text O YYYY-MM-DD (패턴 검증)
hour number — 0~23 정수. 예약 시작 시각
name text O 예약자
dept text X 부서
memo text X 메모
email email X 이메일

중복 예약 차단: (machine, date, hour) 에 UNIQUE 인덱스가 걸려 있어, 두 사람이 동시에
같은 칸을 눌러도 DB 레벨에서 한 명만 성공합니다 (나머지는 HTTP 400).

API 권한: 로그인 없이 쓰는 공용앱이므로 조회/등록/삭제는 공개이고,
수정(update)은 관리자 전용으로 잠겨 있습니다 (비인증 수정 시도 시 HTTP 403).

hour 가 "필수"가 아닌 이유: PocketBase는 숫자 0을 빈 값으로 취급해서,
필수로 두면 0시 예약이 거부됩니다. 대신 min/max(0~23)와 정수 제약으로 검증합니다.

8. 동작 확인 (설치 후 점검용)

# 서버 살아있는지
curl -s http://127.0.0.1:8090/api/health

# 예약 1건 넣어보기
curl -s -X POST http://127.0.0.1:8090/api/collections/reservations/records \
  -H "Content-Type: application/json" \
  -d '{"machine":"진동시험기 1호","date":"2026-07-27","hour":9,"name":"홍길동"}'

# 같은 칸에 또 넣어보기 -> 400 이 나와야 정상 (중복 차단 동작)

9. 다른 플랫폼과 뭐가 다른가요?

가입·계정·인터넷 없이 완전 자립 동작하고, 관리자 화면(예약을 엑셀처럼 직접 편집/삭제)이
공짜로 딸려오는 것이 핵심입니다. 구글시트 방식처럼 별도 관리도구를 만들 필요가 없고,
DB·인증·API가 실행파일 하나에 다 들어 있어 백엔드를 따로 구축할 필요가 없습니다.
