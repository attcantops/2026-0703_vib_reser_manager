# 진동시험기 예약 서버 — 외부 접속 방법 전체 비교

- 작성일: 2026-07-27
- 대상: 라즈베리파이 `192.168.0.222:8090` (E-PocketBase). 향후 회사 NAS 동일 적용
- 용도: **지금 결정하지 않고 기록해 두는 문서.** 나중에 필요해질 때 이 표를 기준으로 고름

> **이 문서의 취급**
> 내부 IP·보안 설계 전제가 있어 공개 저장소에 올리지 않습니다.
> `.gitignore`의 `E-PocketBase/docs/` 규칙으로 제외됩니다.

## 0. 먼저 — 이 앱의 특수 조건

일반적인 "집 서버 외부 접속" 문제와 다른 점이 하나 있고, 이게 선택을 좌우합니다.

| 동작 | 규칙 | 의미 |
|---|---|---|
| 조회 · 등록 · **삭제** | `""` | **인증 없이 누구나** |
| 수정 | `null` | 관리자만 |

사내 폐쇄망에서 로그인 없이 편하게 쓰려고 **의도적으로** 그렇게 만든 설계입니다.
그 환경에서는 합리적입니다. 하지만 외부 접속을 붙이는 순간 이렇게 바뀝니다.

> **주소를 아는 사람은 누구나 예약 전체를 삭제할 수 있다.**
> 앱 화면은 이름이 맞아야 취소되지만, 그건 화면상의 제약일 뿐 API를 직접 부르면 통하지 않습니다.
> 관리자 화면(`/_/`)도 같은 주소에 함께 노출됩니다.

그래서 아래 표의 핵심 열은 **"누가 접속할 수 있는가"** 입니다.
"어떻게 뚫는가"는 부차적입니다.

### 여기서 갈라지는 두 갈래

| 갈래 | 성격 | 이 앱에 적용 시 |
|---|---|---|
| **A. 사설망 확장** (VPN 계열) | 허가된 기기만 참여. 공개 주소가 생기지 않음 | 앱을 고칠 필요 **없음** |
| **B. 공개 노출** (터널·포트포워딩) | 인터넷에 주소가 생김 | **인증을 따로 붙이지 않으면 위험** |

## 2. 항목별 상세

### 1. 같은 LAN / WiFi — 현재 상태

- 주소: `http://192.168.0.222:8090/`
- **폰을 집 WiFi에 연결하면 그대로 열립니다.** 추가 작업 0분, 위험 0.
- 회사 NAS로 가면 **직원들은 전부 이 방식**입니다. 사내망 안에 있으니까요.
- ⚠️ 결론: **외부 접속은 대부분의 경우 필요 없습니다.** 아래 방법들은 "출장 중에도 봐야 한다" 같은
  요구가 실제로 생겼을 때 검토하면 됩니다.

### 2. Tailscale — 외부에서 확인만 할 목적이면 최선

- WireGuard 기반 메시 VPN. 파이와 폰에 각각 설치하고 같은 계정으로 로그인하면,
  LTE에서도 파이가 **집 안에 있는 것처럼** 잡힙니다.
- **공개 주소가 생기지 않습니다.** 0장의 "누구나 삭제 가능" 위험이 성립하지 않습니다.
- 공유기 설정 불필요(NAT 통과), 무료 플랜 100대.
- 단점: 접속할 기기마다 앱 설치+로그인 필요 → **불특정 직원에게 공유하기엔 부적합**.
- 설치:
  ```bash
  curl -fsSL https://tailscale.com/install.sh | sh
  sudo tailscale up
  ```
  폰에는 Tailscale 앱 설치 후 같은 계정 로그인. 이후 `http://<파이의 tailscale IP>:8090`

### 3. ZeroTier

- Tailscale과 성격 동일. 네트워크 ID로 참여하고 관리자가 승인하는 방식.
- 무료 25대. 어느 쪽을 써도 무방하나, 설정 편의는 Tailscale이 낫습니다.

### 4. WireGuard 직접 구축

- 중개 서비스 없이 자체 VPN. 계정 종속이 0이라 가장 "자립적".
- 대신 **공유기에 UDP 포트 개방 + 키 관리**를 직접 해야 하고, 집 IP가 바뀌면 DDNS도 필요합니다.
- 회사 보안 정책상 외부 서비스를 못 쓰는 경우의 대안.

### 5. 공유기 내장 VPN

- 요즘 공유기 상당수가 OpenVPN/WireGuard 서버를 내장합니다(ipTIME 등).
- 공유기 관리 화면에서 켜고 설정 파일을 폰에 넣으면 끝. 4번보다 쉽습니다.
- 파이를 건드리지 않아도 된다는 게 장점.

### 6. Cloudflare Quick Tunnel — 단기 테스트 전용

```bash
cloudflared tunnel --url http://localhost:8090
```
- 계정·도메인·공유기 설정 **전부 불필요**. 실행 즉시 `https://랜덤단어.trycloudflare.com` 발급.
- 집 공인 IP가 노출되지 않고 HTTPS가 자동으로 붙습니다.
- ⚠️ **인증이 없습니다.** URL을 아는 사람은 누구나 예약을 지울 수 있고, 관리자 화면도 노출됩니다.
- ⚠️ 주소는 실행할 때마다 바뀌고, 프로세스를 끄면 사라집니다. **상시 운영 불가.**
- 쓴다면 반드시 아래 3개를 같이:
  1. 관리자 로그인 IP 화이트리스트 (`superuser ips`) 로 LAN 외 로그인 차단
  2. 테스트 직전 백업 (`sudo /opt/vibres/backup.sh`)
  3. **테스트 끝나면 즉시 종료**

### 7. Cloudflare Named Tunnel

- 고정 주소(`vib.cantops.biz` 등)를 쓰는 정식 터널. 계정 + **Cloudflare에 등록된 도메인** 필요.
- ⚠️ 전제 확인 필요: `cantops.biz`는 현재 **가비아 DNS**를 씁니다. Cloudflare로 네임서버를
  옮기거나 서브도메인을 위임해야 합니다. 회사 도메인이라 **협의 대상**입니다. `[확인 필요]`
- 단독으로는 6번과 위험이 같습니다. 반드시 8번과 함께.

### 8. Named Tunnel + Cloudflare Access — 상시 운영한다면 이것

- 터널 앞에 **인증 게이트**를 답니다. 허용한 이메일만 통과합니다.
- 접속하면 이메일로 일회용 코드가 오고, 인증해야 앱이 보입니다.
- **앱을 고치지 않고도** 로그인을 붙이는 효과. 0장의 문제가 해소됩니다.
- 무료 플랜 50 사용자. 회사 규모에 충분합니다.
- 이 앱을 사외에서 상시 쓰겠다면 **사실상 유일하게 권할 만한 구성**입니다.

### 9. Tailscale Funnel

- Tailscale 노드를 인터넷에 공개하는 기능. 2번의 장점(설정 간편)에 6번의 위험이 붙습니다.
- 인증이 없으므로 이 앱에는 6번과 같은 주의가 필요합니다.

### 10. ngrok

- 6번의 대안. 계정이 필요하고, 무료 플랜은 주소가 매번 바뀌며 동시 터널 1개 제한.
- Cloudflare 계정을 이미 보유하고 있으므로 굳이 선택할 이유는 적습니다.

### 11. 포트포워딩 + DDNS — 비권장

- 공유기에서 8090을 파이로 전달하고, 집 IP가 바뀌니 DDNS를 겁니다.
- **집 공인 IP가 그대로 드러나고**, HTTPS도 직접 붙여야 합니다.
- ⚠️ **22번(SSH)은 절대 열지 마세요.** 파이는 SSH 비밀번호 로그인이 허용돼 있고
  `pi` 계정이 무암호 sudo(`NOPASSWD: ALL`)입니다. 뚫리면 장비 전체를 내줍니다.
  인터넷의 SSH 무차별 대입은 상시로 돌아갑니다.

### 12. 리버스 프록시 + 인증

- Nginx/Caddy를 앞에 두고 Basic 인증이나 Authelia 같은 인증 계층을 붙입니다.
- 외부 서비스 종속이 없다는 게 장점, 인증서·설정·유지보수를 직접 해야 하는 게 단점.
- 사내에 이미 리버스 프록시가 있다면 자연스러운 선택.

### 13. 시놀로지 QuickConnect

- 시놀로지 NAS로 이관한 뒤 쓸 수 있는 선택지. 포트 개방 없이 외부 접속을 제공합니다.
- DSM 계정 인증을 걸 수 있는지, 컨테이너로 띄운 8090을 어떻게 노출할지는
  실제 NAS 모델과 DSM 버전에 따라 다릅니다. `[확인 필요]`

## 4. 근본 해결책 — 앱에 인증 넣기

위 방법들은 전부 **앱 바깥에서** 접근을 통제하는 것입니다.
사외 상시 운영이 정식 요구사항이 되면, 결국 앱 안에 인증을 넣는 게 맞습니다.

PocketBase는 인증이 내장돼 있어 작업이 크지는 않습니다.

1. `users` 컬렉션 활성화 (PocketBase 기본 제공)
2. `reservations`의 규칙을 바꿈
   ```
   listRule   = ""                        (조회는 공개 유지 가능)
   createRule = "@request.auth.id != ''"  (로그인해야 예약)
   deleteRule = "@request.auth.id != ''"  (로그인해야 취소)
   ```
3. 예약 레코드에 소유자 필드를 두면 **"본인만 취소"** 를 DB 레벨에서 강제할 수 있습니다.
   지금은 화면에서 이름을 비교하는 방식이라 API로 우회됩니다.
4. 프론트에 로그인 화면 추가

⚠️ 다만 이건 **설계 변경**입니다. "로그인 없이 편하게"라는 현재 전제를 버리는 것이라,
사내 사용자들의 편의와 맞바꾸는 결정입니다. 사내망 전용으로 간다면 하지 않는 게 맞습니다.

요구 조건이 구체화되면서 선택지가 좁혀졌습니다.

| 조건 | 탈락하는 방법 |

| **파이 상시 가동 → 고정 주소 필요** | 6 (Quick Tunnel, 재시작마다 변경) |
| **인증 필요** (삭제 권한이 공개라서) | 9·10·11 |

남은 것이 **8번(Named Tunnel + Access)** 이고, 이것만이 **앱을 고치지 않고** 인증을
붙일 수 있습니다. Cloudflare가 문 앞에서 막으므로 인증 실패자는 예약 API에 닿지 못합니다.

**도메인은 회사 도메인이 아니라 개인 도메인으로 갑니다.**
`cantops.biz` 를 쓰려면 네임서버를 Cloudflare로 옮겨야 하고 이는 회사 승인 사안인데,
정작 사내망에서는 이 기능을 쓰지 않습니다. 안 쓸 기능 때문에 승인 절차를 밟는 것은
낭비입니다. 개인 도메인은 `.com` 기준 연 $10~11 이고 당일 처리됩니다.

**무료 대안도 있었습니다** — Tailscale Funnel + Caddy 기본인증 조합이면 비용 없이
같은 결과(고정 URL·앱 불필요·인증)를 얻습니다. 차이는 이메일 OTP 대신 공용 비밀번호
하나라는 점이고, 도메인이 다른 개인 프로젝트에도 재사용된다는 점을 고려해 유료를 택했습니다.

실제 설정 절차는 저장소의 **`E-PocketBase/외부접속_설정계획.md`** 에 있습니다.

**진행 상태**: 도메인 구매 대기 중. 구매 후 4장(설치 절차)부터 진행.
