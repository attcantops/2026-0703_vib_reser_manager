## 0. 요청 전 확인 사항 (요청자가 먼저 확인)

⚠️ **이 항목이 확인되지 않으면 설치해도 목적을 달성하지 못합니다.**

10층과 12층의 네트워크 대역이 분리되어 있어 층간 파일공유(`\\`)가 되지 않는 상태입니다.

**확인 방법** — 10층 PC와 12층 PC에서 각각 브라우저로 접속:


|---|---|
| 양쪽 다 열림 | ✅ 진행 가능 |
| 한쪽만 열림 | ⚠️ 설치 전에 방화벽·라우팅 협의 필요 (아래 5장에 문의) |
| 양쪽 다 안 열림 | ⚠️ NAS 접근 자체가 막힌 상태. 별도 협의 |

## 1. 무엇을 설치하는가

진동시험기 예약을 관리하는 **사내 웹 애플리케이션**입니다.
직원이 브라우저에서 날짜·시간을 선택해 예약하고, 중복 예약을 자동으로 차단합니다.

| 항목 | 내용 |
|---|---|
| 구성 | Docker 컨테이너 **1개** |
| 베이스 이미지 | Alpine Linux 3.20 (약 8MB) |
| 애플리케이션 | PocketBase 0.39.9 (Go 단일 실행파일, 약 31MB) |
| 데이터베이스 | SQLite (컨테이너 내장, 별도 DB 서버 불필요) |
| 디스크 사용량 | 약 50MB. 데이터 증가량 **연 1MB 미만** |
| 메모리 사용량 | 유휴 시 약 30~50MB |
| 외부 통신 | **없음** (최초 이미지 빌드 시에만 인터넷 필요, 이후 완전 사내 동작) |
| 필요 포트 | **1개** (기본 8090, 충돌 시 변경 가능) |

**개인정보 취급 없음**: 저장 항목은 예약자 이름·부서·메모·이메일(선택)입니다.

## 3. 설치 절차 (DSM 7.x / Container Manager)

### 3-1. 소스 준비

아래 저장소의 `E-PocketBase` 폴더를 NAS에 올립니다.

```
https://github.com/attcantops/2026-0703_vib_reser_manager
```

**방법 A — 요청자가 압축파일로 전달** (권장, NAS에서 인터넷 접근 불필요)
1. 요청자가 전달한 `E-PocketBase.zip` 을 받습니다.
2. **File Station** → `/volume1/docker/` 아래에 `vibres` 폴더 생성 후 압축 해제
3. `Dockerfile`, `docker-compose.yml`, `pb_public/`, `pb_migrations/` 가 보이면 정상

**방법 B — NAS에서 직접 내려받기**
```
File Station 또는 SSH 로 /volume1/docker/vibres 에 저장소 내용 배치
```

### 3-2. 포트 확인

기본값은 **8090** 입니다. 이미 사용 중이면 `docker-compose.yml` 을 열어
**왼쪽 숫자만** 바꿔 주세요.

```yaml
ports:
  - "8090:8090"      # 예: "8095:8090" 으로 변경 (오른쪽은 그대로)
```

### 3-3. Container Manager 로 실행

1. **Container Manager** 실행
2. 왼쪽 **프로젝트** → **생성**
3. 프로젝트명 `vibres`
4. 경로: `/volume1/docker/vibres` 선택
5. 소스: **기존 docker-compose.yml 사용** 선택
6. **다음 → 완료**

빌드가 시작됩니다 (**최초 1회 3~5분**, 인터넷 연결 필요).
빌드 중 GitHub 에서 PocketBase 실행파일을 내려받습니다.

> ⚠️ NAS 에서 외부 인터넷이 차단돼 있으면 빌드가 실패합니다.
> 그 경우 요청자에게 알려 주시면 **빌드 완료된 이미지 파일**로 다시 전달드리겠습니다.

### 3-4. 정상 동작 확인

브라우저에서 접속:

```
http://【NAS IP】:【포트】/
```

날짜 선택과 시간 그리드가 있는 **한국어 예약 화면**이 나오면 완료입니다.

## 5. 네트워크 관련 문의 (0장에서 한쪽만 접속된 경우)

10층과 12층에서 모두 접속되어야 하는 시스템입니다. 현재 층간 파일공유(SMB)가
되지 않는 상태인데, **웹(HTTP) 접속도 동일하게 차단되는지** 확인 부탁드립니다.

- 차단된다면: 해당 포트에 한해 층간 접근 허용이 가능한지
- 불가하다면: 요청자 측에서 외부 호스팅(Cloudflare) 방식으로 전환 검토 예정

## 6. 예상 질문

**Q. 외부(인터넷)로 나가는 통신이 있습니까?**
없습니다. 최초 이미지 빌드 때만 GitHub 에서 실행파일을 받고, 이후에는 사내에서만 동작합니다.
외부 서비스 계정·API 키·클라우드 연동이 일절 없습니다.

**Q. NAS 자원을 얼마나 씁니까?**
유휴 시 메모리 30~50MB, 디스크 약 50MB 입니다. 예약 데이터는 연 1MB 미만으로 증가합니다.

**Q. 로그인이 있습니까?**
사용자 화면은 **로그인이 없습니다** (사내망 전용 설계, 이름 입력으로 구분).
관리 화면은 별도 관리자 계정으로 보호되며, 계정은 설치 후 요청자가 직접 생성합니다.

**Q. 백업은 어떻게 합니까?**
데이터가 `/volume1/docker/vibres/pb_data` 폴더에 SQLite 파일로 저장됩니다.
**이 폴더만 기존 NAS 백업 정책에 포함**해 주시면 됩니다. 앱 자체에도 자동 백업 기능이 있습니다.

**Q. 제거하려면?**
Container Manager 에서 프로젝트 삭제 후 `/volume1/docker/vibres` 폴더를 지우면 됩니다.
시스템에 남기는 것이 없습니다.

**Q. 업데이트는 누가 합니까?**
요청자가 Container Manager 에서 프로젝트를 재빌드하는 방식으로 직접 수행합니다.
중단 시간은 10~20초이며, 데이터는 별도 폴더에 있어 영향받지 않습니다.
