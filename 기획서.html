진동시험기 예약관리 시스템 — 기획서 (Plan)

작성일: 2026-07-03 · 상태: 기획 단계 (구현 전)
목적: 신규 도입되는 공용 진동시험기를 "예약 후 사용" 체계로 관리한다.

1. 배경 · 목표

  • 진동시험기가 신규로 들어오며, 공용 장비라 여러 부서/인원이 나눠 쓴다.
  • 예약 없이 쓰면 겹침·충돌·누가 쓰는지 모름 문제가 생긴다.
  • 기존 "계측기 관리" 프로젝트의 철학을 계승 → 강제 통제보다, 자유롭게 쓰되 자연스럽게 잘 관리되게 한다.

성공 기준(무엇이 되면 성공인가)
1. 사용 전 누구나 30초 안에 예약할 수 있다.
2. 같은 시간에 두 사람이 예약되는 일이 절대 없다. (충돌 0)
3. "지금/오늘/이번 주 누가 쓰는지"가 한 화면에 보인다.

2. 사용자 · 역할 (업계 표준: Role 기반)

역할 할 수 있는 일
일반 사용자 예약, 본인 예약 취소, 현황 조회
관리자(장비 담당) 전체 예약 취소/변경, 통계 조회, 공지, 정기점검 시간 차단
(선택) 승인자 "관리자 승인 후 확정" 정책을 쓸 경우에만

소규모 조직이라 로그인/계정을 무겁게 두지 않고, 이름·부서 입력 + 관리자 비밀번호 최소 방식 권장.

3. 핵심 기능 — MVP vs 확장

예약 시스템의 업계 표준은 슬롯(Slot) 기반 예약 + 충돌 방지다. 이를 단계로 나눈다.

Phase 1 — MVP (먼저 반드시 만드는 것)

  • [ ] 날짜 선택 (달력)
  • [ ] 시간 타임테이블: 1시간 단위 슬롯 (예: 09~18시, 9칸)
  • [ ] 빈 슬롯 클릭 → 예약 (이름 · 부서 · 용도 입력)
  • [ ] 중복 방지: 이미 찬 시간은 잠금, 선착순 즉시 확정 (동시요청 안전 처리)
  • [ ] 예약 현황표: 그날 타임테이블에 예약자 표시
  • [ ] 본인 예약 취소
  • [ ] 지난 시간은 예약 불가

Phase 2 — 확장 (운영하며 추가)

  • [ ] 주간/월간 캘린더 뷰
  • [ ] 여러 장비 지원 (진동시험기 2·3호기 늘어날 때)
  • [ ] 예약 상태 관리: 신청 → 확정 → 사용중 → 완료 / 노쇼(No-show)
  • [ ] 알림: 예약 확정·시작 30분 전 (사내 메신저/이메일)
  • [ ] QR 코드: 장비에 붙여두고 현장에서 스캔 → 바로 예약/체크인 (기존 계측기 프로젝트 QR 자산 재활용)
  • [ ] 통계 대시보드: 장비 가동률, 부서별 사용시간, 노쇼율
  • [ ] 정기점검/사용불가 시간 차단 (관리자)

Phase 3 — 운영 자동화

  • [ ] 사내 PC 상시 구동 + 부팅 시 자동 실행 (윈도우 작업 스케줄러)
  • [ ] DB 자동 백업 (일 단위)

4. 예약 정책 (규칙 — 업계 표준 반영, 우리에 맞게 조정)

항목 기본안 비고
예약 단위 1시간 요청사항
운영 시간 09~18시 장시간 시험 필요 시 08~20 또는 24시간으로 변경 가능
확정 방식 선착순 즉시 확정 담당자 개입 최소화 (자유로운 관리 철학)
취소 본인 취소 가능, 관리자는 전체 취소 시작 임박 취소 시 노쇼와 구분
독점 방지 (선택) 1인 1일 최대 N시간 제한 초기엔 미적용, 문제 생기면 도입
노쇼 (Phase 2) 사용 안 하면 기록 문화적 관리 수단

정책은 "강제 규칙"보다 "보이게 만들어 서로 배려" 방향. 제한은 최소로 시작하고 필요 시 강화.

5. 데이터 모델 (SQLite)

reservations
├─ id        (PK)
├─ machine   장비명 (예: "진동시험기 1호기")
├─ date      YYYY-MM-DD
├─ hour      시작 시각 (9 = 09~10시)
├─ name      예약자 이름
├─ dept      부서
├─ purpose   사용 목적/시험명
├─ status    확정/사용중/완료/노쇼 (Phase 2)
└─ created   생성 시각

제약: UNIQUE(machine, date, hour)  ← 중복 예약을 DB 차원에서 원천 차단

7. 기술 스택 (업계 표준 × 우리 상황)

구분 선택 이유
백엔드 Python (표준 라이브러리 또는 Flask) 기존 계측기 프로젝트 자산·역량 재활용
DB SQLite 소규모 예약 시스템 업계 표준, 설치·서버 불필요, 파일 1개
프론트 HTML/CSS/JS (프레임워크 X) 이 규모엔 순수 웹이 가장 가볍고 유지보수 쉬움
배포 사내 PC 1대 = 예약 서버 인터넷/가입 불필요, 사내망에서 브라우저로 접속

핵심 원칙: 의존성 최소화 → "끊이지 않고" 돌아가는 것을 최우선. Python만 있으면 실행되게.

대안 비교
- (A) 사내 PC 서버 + SQLite ✅ 추천 — 데이터 공유 O, 설치 간단, 유지 쉬움
- (B) 구글 시트/앱스스크립트 — 외부 접속 O, 초기 연동 설정 필요
- (C) 각자 브라우저 저장(localStorage) ❌ — 서로 예약이 안 보여 예약관리 목적에 부적합

8. 배포 · 운영

  1. 사내 PC 한 대를 "예약 서버"로 지정, python app.py 상시 실행.
  2. 다른 PC는 http://서버IP:8000 으로 브라우저 접속 (설치 불필요).
  3. 부팅 시 자동 실행 등록(작업 스케줄러) → 사람이 신경 안 써도 계속 켜져 있음.
  4. reservations.db 파일을 매일 백업 폴더로 복사.

10. 확정이 필요한 사항 (Phase 0)

구현 착수 전 아래만 정해주시면 됩니다. (미정 시 굵은 기본안으로 진행)

  1. 운영 시간: 09~18시 / 08~20시 / 24시간(장시간 시험) 중?

  5. 입력 항목: 이름·부서·용도 외에 필요한 것? (예: 연락처, 시험 종류, 시료 수)
