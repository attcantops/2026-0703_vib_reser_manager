# 진동시험기 예약 — Next.js + Vercel 버전 설치/실행 방법

## (a) Next.js / Vercel 이란? (1문단)
Next.js 는 React 기반의 **풀스택 프레임워크**입니다. 즉 화면(React 컴포넌트)과
백엔드(API)를 **한 프로젝트 안에서** 함께 만듭니다. 이 프로젝트는 최신 방식인
**App Router** 구조를 씁니다. `app/page.jsx` 가 화면이고, `app/api/**/route.js`
파일들이 백엔드 **API Route**(서버 코드)입니다. 화면은 `fetch('/api/...')` 로
같은 프로젝트의 API 를 호출합니다. 코드를 GitHub 에 올리고 Vercel 에 연결해 두면,
**git push 할 때마다 Vercel 이 자동으로 빌드·배포**해 줍니다.

## (b) 가입 (필요한 계정)
- **Vercel** 계정이 필요합니다: https://vercel.com → **GitHub 계정으로 로그인(권장)**.
  GitHub 로 로그인하면 배포 연결이 가장 간단합니다.
- (배포하려면) **GitHub** 계정도 필요합니다: https://github.com

## (c) 로컬에서 실행 (내 PC에서 먼저 확인)
사전준비: Node.js(LTS) 설치 — https://nodejs.org

```bash
# 이 폴더(D-NextJS-Vercel)에서
npm install       # 의존성 설치 (최초 1회)
npm run dev       # 개발 서버 실행
```

그다음 브라우저에서 **http://localhost:3000** 접속 → 예약 화면이 뜹니다.

## (d) 배포 (인터넷에 올리기)
1. 이 폴더를 **GitHub 저장소**에 올립니다(push).
2. https://vercel.com → **Add New… → Project → Import**
   → 방금 올린 GitHub 저장소를 선택합니다.
3. 별도 설정 없이 **Deploy** 를 누르면 Vercel 이 자동 빌드·배포합니다.
4. 이후에는 **git push 만 하면 자동으로 재배포**됩니다.

## (e) ⚠️ 인메모리 DB 의 한계 & 운영 DB 교체
지금 이 앱의 데이터는 `app/lib/db.js` 안의 **서버 메모리(배열)** 에 저장됩니다.
- **서버를 재시작하면 데이터가 전부 초기화**됩니다(코드 저장/재배포 포함).
- Vercel 같은 서버리스 환경에서는 요청마다 다른 인스턴스가 떠서 데이터가
  유지되지 않을 수 있습니다. → 지금 버전은 **"동작 감 잡기"용**입니다.

실제 사내 운영에 쓰려면 진짜 DB 로 바꾸세요:
- **Vercel Postgres** 또는 **Supabase** 를 권장합니다.
- 교체는 `app/lib/db.js` 의 함수 몸통
  (`getReservations` / `addReservation` / `removeReservation`)만
  DB 쿼리로 바꾸면 됩니다. 나머지 코드(화면·API)는 그대로 재사용됩니다.
- 파일 안 주석의 **[교체 지점 ①/②]** 표시와 예시 SQL(테이블/`UNIQUE` 제약)을 참고하세요.
- 중복예약 방지(`UNIQUE(machine, date, hour)`)는 실제 DB 에서는 테이블에
  **UNIQUE 인덱스**로 걸어 두는 것이 안전합니다.

## (f) 다른 플랫폼과 뭐가 다른가 (1~2줄)
구글시트/Apps Script 버전이 "시트를 DB 삼아 간단히" 가는 방식이라면, 이 Next.js +
Vercel 버전은 **React 화면 + 서버 API 를 한 프로젝트로 만드는 정식 웹앱** 방식이라
확장성·성능·커스터마이징이 크고, 진짜 DB(Postgres/Supabase)와 자연스럽게 연결됩니다.
