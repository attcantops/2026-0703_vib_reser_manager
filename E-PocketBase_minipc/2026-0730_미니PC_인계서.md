# 미니PC 인계서 — E-PocketBase 설치 (2026-07-30)

**읽는 대상: 미니PC(192.168.2.86)에서 실행되는 Claude Code.**

12층 데탑(192.168.2.24)에서 작업하다 넘긴 문서다. 원격으로 설치를 끝내려 했으나
미니PC의 원격 실행 서비스가 전부 닫혀 있어(아래 표) RDP 수동 중계밖에 남지 않았다.
그래서 미니PC에서 직접 이어받는다. **당신은 미니PC 위에서 돌고 있으므로 그 제약이 없다.**

목표는 하나다: **이 미니PC에 예약 서버를 올리고, 10층에서 접속되는지 판정한다.**
후자가 배포 방향(사내 자체호스팅 vs Cloudflare)을 가른다.

---

## 확인된 사실 — 2026-07-30, 12층 데탑에서 측정

다시 재지 말 것. 이미 확인됐다.

| 항목 | 값 |
|---|---|
| 미니PC | `192.168.2.86` (12층, GW 192.168.2.1) |
| 12층 데탑 | `192.168.2.24` (같은 서브넷 — 확인목록의 "12층 다른 PC" 가 이 데탑이다) |
| 3389 (RDP) | **열림** — 미니PC 살아있고 12층에서 닿음 |
| 8090 | 닫힘 — `install.ps1` 미실행. 정상이다 |
| 445 (SMB) | **막힘** — 층간만이 아니라 **같은 층에서도** 파일공유 불가 |
| 5985/5986 (WinRM) | 닫힘 |
| 22 (SSH) / 135 (WMI) | 닫힘 |
| `ping 192.168.2.86` | **실패(TimedOut)** — 윈도우 ICMP 기본 차단. 고장 아님 |

`ping` 이 같은 서브넷에서도 실패했다는 게 중요하다. 이유는 아래 "판정 기준" 참조.

## 할 일

### 1. 저장소 확보

`install.ps1` 은 **자기 옆의 `..\E-PocketBase` 를 읽는다.** 앱 본체(`pb_public`,
`pb_migrations`, `pb_hooks`)는 그쪽에 한 벌만 있고, `E-PocketBase_minipc\` 에는
윈도우 설치 수단만 있다. 그래서 **저장소 전체**가 미니PC 안에 있어야 한다.
SMB 가 막혀 있으므로 데탑에서 복사해 올 수는 없다 — git 으로 받아야 한다.

```powershell
$repo = "C:\src\2026-0703_vib_reser_manager"
$url  = "https://github.com/attcantops/2026-0703_vib_reser_manager"
if (Test-Path "$repo\.git") { git -C $repo pull }
else { New-Item -ItemType Directory -Force (Split-Path $repo) | Out-Null; git clone $url $repo }
```

git 이 없으면 zip 으로 받아도 된다 (읽기는 공개되어 있다):

```powershell
Invoke-WebRequest "$url/archive/refs/heads/main.zip" -OutFile "$env:TEMP\repo.zip"
Expand-Archive "$env:TEMP\repo.zip" "C:\src" -Force   # -> C:\src\2026-0703_vib_reser_manager-main
```

이미 저장소가 있다면 `git log -1` 로 `9e6aa4f` 이상인지 확인한다. 그 아래면 `pull` 한다.

### 2. 설치

**관리자 권한 PowerShell** 이어야 한다. 스크립트가 첫머리에서 검사하고 아니면 중단한다.

```powershell
cd "$repo\E-PocketBase_minipc"
powershell -ExecutionPolicy Bypass -File .\install.ps1
```

멱등하다. 막히면 고치고 그냥 다시 돌리면 된다. **`pb_data`(예약 데이터)는 건드리지 않는다.**

하는 일: PocketBase 0.39.9(파이와 동일 버전 고정) 다운로드 → 앱 파일을
`C:\vibres\` 로 복사 → 방화벽 8090·ICMP 허용 → 부팅 자동시작(작업 스케줄러
`vibres`, SYSTEM 계정) → 기동·헬스체크.

**예상 실패 지점**: 1단계에서 PocketBase 를 GitHub 에서 받는다. 사내에서 외부가
막혀 있으면 여기서 멈춘다. 그 경우 인터넷 되는 PC 에서 받아 `C:\vibres\pocketbase.exe`
에 두고 다시 실행하면 다운로드를 건너뛴다.

### 3. 미니PC 자신에서 확인

```powershell
Get-ScheduledTaskInfo -TaskName vibres
Get-Process pocketbase
netstat -ano | findstr :8090          # 0.0.0.0:8090 이어야 한다
Invoke-WebRequest http://127.0.0.1:8090/api/health -UseBasicParsing
ipconfig | findstr IPv4               # 192.168.2.86 맞는지
```

`127.0.0.1:8090` 으로만 듣고 있으면 밖에서 안 보인다. `0.0.0.0` 이어야 한다.

### 4. 메일 경로 확인 (곁가지 — 당신이 여기서 할 수 있다)

```powershell
Test-NetConnection 8.8.8.8 -Port 443
Test-NetConnection smtp.hiworks.com -Port 465
Test-NetConnection smtp.hiworks.com -Port 587
```

메일은 예약의 전제가 아니다. 전부 False 여도 예약은 정상 동작한다. 이 결과는
알림 방식(SMTP 직결 vs HTTPS 메일 API)만 가른다.

### 5. 사용자에게 넘길 것 — 당신이 미니PC 에서 할 수 없는 것

- **12층 확인**: 12층 데탑(192.168.2.24) 브라우저에서 `http://192.168.2.86:8090`
  — 미니PC 자신에서 열어보는 건 이 확인이 못 된다
- **10층 확인**: 10층 PC 브라우저에서 같은 주소 ← **배포 방향을 정하는 지점**
- **관리자 계정 생성**: `http://192.168.2.86:8090/_/` 최초 접속

`ipconfig` 결과와 헬스체크 통과 여부를 알려주고, 위 세 개를 사용자에게 요청한다.

## 판정 기준 — ping 을 믿지 말 것

`10층에서 안 열림` 일 때 원인을 좁히는 방식이다.

```powershell
Test-NetConnection 192.168.2.86 -Port 3389    # 패킷이 층을 넘는가  ← 라우팅 판정
Test-NetConnection 192.168.2.86 -Port 8090    # 8090 만 막힌 것인가
tracert -h 5 192.168.2.86
```

| 12층 | 10층 | 뜻 | 다음 |
|---|---|---|---|
| ✅ | HTTP ✅ | 층간 HTTP 라우팅 있음 | **사내 자체호스팅 확정.** 미니PC 하나로 끝 |
| ✅ | 3389 ✅ / HTTP ❌ | 통신은 되는데 포트가 막힘 | 전산팀에 8090 개방 요청 — 협의 여지 있음 |
| ✅ | 3389 ❌ | 층간 라우팅 자체가 없음 | Cloudflare 라이브 버전으로 전환 |
| ❌ | — | 미니PC 방화벽·서비스 문제 | 라우팅 판단 불가. 설치부터 다시 |

**판정에 `ping` 을 쓰지 말 것.** 원래 확인목록은 "10층 ping 실패 = 층간 라우팅 없음
= Cloudflare 전환" 이었는데, **같은 12층 서브넷의 데탑에서도 ping 이 실패했다.**
윈도우가 ICMP 를 기본 차단할 뿐 라우팅은 멀쩡했고 3389 은 열려 있었다. 그대로 뒀으면
쓸 수 있는 사내 호스팅을 버리고 외부 호스팅으로 가는 오판을 할 수 있었다.
`install.ps1` 에 ICMP 허용을 넣어 고쳤지만(커밋 `9e6aa4f`), 경로 중간 장비가 ICMP 를
막으면 여전히 실패한다. **3389 으로 판정한다.**

## 하지 말 것

- **미니PC 를 12층 네트워크에서 빼지 말 것.** 책상으로 옮기는 건 괜찮지만 같은 12층
  허브에 꽂혀 있어야 한다. MAC 등록제라 10층·12층 IP 를 각각 받아뒀지만 랜선이 하나여서
  한 번에 한 층에만 붙는다. 층을 옮기면 IP 가 바뀌어 지금까지의 확인값이 전부 무효가 되고,
  10층 테스트도 의미를 잃는다. **10층 확인은 10층에 있는 *다른* PC 로 한다.**
- **`E-PocketBase\` 의 `install.sh` / `update.sh` / `backup.sh` / `Dockerfile` /
  `docker-compose.yml` 을 쓰지 말 것.** 라즈베리파이·리눅스용이다. 미니PC 는
  `E-PocketBase_minipc\install.ps1` 만 쓰고, 앱 파일만 `E-PocketBase\` 에서 가져간다.
- **앱 파일을 `E-PocketBase_minipc\` 로 복제하지 말 것.** 두 벌이 되면 화면을 고칠 때
  한쪽만 고쳐지는 사고가 난다. 본체는 `E-PocketBase\` 한 벌이다.
- **`C:\vibres\pb_data\` 를 건드리지 말 것.** 예약 데이터다.

## git 계정 — 커밋 전에 확인할 것

이 저장소는 **`attcantops` / `att.cantops@gmail.com`** 을 쓴다. 사용자는 계정을
작업 종류별로 나눠 쓴다 — 웹 관련이 이 계정이고, 그 밖의 기존 작업은 다른 계정이다.

12층 데탑에서 전역 설정(`btkang` / `azzmo@naver.com`)을 그대로 믿고 커밋했다가
작성자가 틀려 `--amend --reset-author` 로 되돌려야 했다. 푸시도 403 이 났다.
**미니PC 의 전역 설정도 다를 수 있으니, 커밋 전에 저장소 로컬로 박아둘 것:**

```powershell
git -C $repo config user.name  "attcantops"
git -C $repo config user.email "att.cantops@gmail.com"
git -C $repo log -3 --format="%h %an <%ae> %s"    # 이력과 맞는지 확인
```

푸시가 403 이면 자격증명 문제다. **전역 자격증명을 지우지 말 것** — 다른 저장소가
쓴다. remote URL 에 계정명을 박아 계정별로 분리하는 쪽으로 푼다:

```powershell
git -C $repo remote set-url origin "https://attcantops@github.com/attcantops/2026-0703_vib_reser_manager.git"
```

읽기(clone/pull)는 공개되어 있어 인증이 필요 없다. 설치만 할 거면 푸시는 신경 쓸 필요 없다.
